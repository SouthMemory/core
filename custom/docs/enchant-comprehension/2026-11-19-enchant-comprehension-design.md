# 附魔领悟与多向强化 — 设计说明

**日期：** 2026-11-19  
**状态：** 框架完成（一期 + Batch2–5 已验收；运行时仅 `enchant_line`）  
**落地方式：** 方案 B（统一运行时 + 分批灌内容）  
**工程手册：** [2026-11-20-enchant-comprehension-engineering.md](./2026-11-20-enchant-comprehension-engineering.md)

## 1. 意图与动机

在 1.12 私服上，把「分解/施放领悟」和「附魔多级成长」收成一套长期可玩的框架：玩家通过附魔行为与分解行为推进配方知识，把装备特效与原版附魔都纳入可成长的 line；试验已证明技术可行，本设计用于收口规则并指导分批实现。

## 2. 目标 / 非目标 / 反目标

**目标**
- 统一「底座 + 方向链」模型，覆盖：原版附魔、装备命中触发、装备光环（含 on-equip 实为触发者）。
- 按效果签名分型：纯数值单轴；含触发/持续结构者真·多向。
- 任意部位可分解领悟；配方锁同部位（与原版附魔一致：锁持握/栏位，不锁武器子类或护甲材质）。
- 试剂规则生成；分解领悟与施放领悟双入口、概率可配置。
- 强化附魔**不**灵魂绑定，带强化的装备可交易流通。

**非目标（本期）**
- 一次生成全库所有 line 的完整数值终表。
- 重做原版训练师/卷轴获取原版本体的方式。
- 客户端大改 UI（技能书互斥可用现有 rank/替换机制；确认框可用插件辅助）。

**反目标**
- 假强化（无 ICD 却做减 CD 等无杠杆方向）。
- 分解可跳级学会方向 1 或更高档，破坏施放进阶循环。
- 错位附魔（头盔配方打武器等）。

## 3. 约束

- 经典客户端学法术包为 **uint16**：自定义法术 ID 必须 `< 65536`。
- 配方与附魔行以 **DBC 预生成** 为主（Spell / SpellItemEnchantment / SkillLineAbility），服务端 DataDir 与客户端 patch 同步。
- 现有试验：`EnchantComprehensionMgr`、变体表、削骨/旋风 spike、冲击式 `EnchantUpgradeMgr` —— 方案 B 下逐步迁入统一模型，不要求一夜删除。
- 配置：分解领悟概率、施放领悟概率等进 `mangosd.conf`。

## 4. 方案选择

| 方案 | 摘要 | 取舍 |
|------|------|------|
| A 一次重做 | 换掉双 Mgr，全库一次生成 | 干净但风险大 |
| **B 统一运行时 + 分批内容（选定）** | 先统一数据/运行时，用少数 line 跑通，再按类型灌内容 | 可玩可迭代 |
| C 几乎只做数据 | 逻辑尽量离线 | 运行时仍少不了施放/分解/互斥 |

**选定 B：** 规则已是大框架，内容必须分批；运行时一张网，生成器当生产线。

## 5. 核心规则（已对齐）

### 5.1 Line 结构

- 等级从 **0** 起。例：`(十字军) → 迅疾1 → 迅疾2 → 迅疾3` 为一条完整方向链。
- 不同方向是不同链，但共享同一 **rank 0 底座**。
- **单轴**（纯 +属性/抗性/技能等）：仅一条「数字变大」的链。
- **多轴**（触发结构、周期、持续、吸收等）：2～3 条方向；无杠杆不开轴。
- 分类按 **效果签名**，不按物品字段表面「光环 vs 触发」：  
  - A 族纯被动数值 → 单轴  
  - B 族含 PROC/周期等（含正义之手类 on-equip+PROC）→ 多向  

### 5.1.1 B 族默认三向模板（已锁定）

默认固定为三向（顺序无关，互斥）：

1. **迅疾**（触发率↑）  
2. **效果强度轴选 1**（强效 / 破甲 / 裂法 / 疾风 / 厚盾 / 凶猛 / 饕餮 … 按主效果签名挑）  
3. **时间轴选 1**（延展 / 急促 / 缄默·震慑类时长 … 有持续用延展，有周期用急促，有控制时长用对应轴）  

**结构轴**（回响 / 连击 / 双蚀 / 反震 / 残影 / 范围 …）仅留给签名特殊的招牌特效，**不当默认三件套**。  
**连贯（ICD↓）** 不进默认模板；仅当效果真有 ICD、且时间轴更适合用连贯而非延展/急促时，可作为时间轴的替补人选。无 ICD 不得开减 CD。

### 5.2 学习与技能书

- **原版本体**（训练师/卷轴等）：**不可**通过领悟学会。
- **特效底座 rank 0**：无训练师者，由 **分解** 领悟获得。
- 同向 **1/2/3 在技能书互斥**，学会高档覆盖低档；底座（原版本体）与方向档可并存（原版本体不因学会迅疾3 而消失）。
- 低 rank 是领悟高 rank 的前提；只能逐级。

### 5.3 分解领悟 vs 施放领悟

- 两者均有概率，配置可调。
- **进阶（学到当前+1）只靠施放附魔触发领悟。**
- **分解只用于补齐/巩固「等级 ≤ 装备当前该附魔等级」的配方**，且仍须满足逐级前提。  
  → 装备仅为底座（rank 0）时，分解**不能**悟出方向 1。
- 分解池可包含：装备固有特效相关 line，以及装备上**当前永久附魔**所属 line（在等级上限规则内）。

### 5.4 施放到装备

- **可直接施放已知最高档**到装备（取消「装备状态必须从 0 爬到顶」）。
- 换方向 = 覆盖为另一方向对应等级（产品语义：换向重置进度）。
- **不**使用灵魂绑定附魔旗；装备可交易流通。

### 5.5 部位

- 任意部位装备均可作为分解领悟来源（在候选规则内）。
- 配方 `EquippedItemClass` / InvTypes 与原版一致：**锁部位/持握，不锁武器子类或布皮甲。**

### 5.6 试剂

- 规则生成：从来源装 **分解产物** 中选 1 类 + 从「相近物品等级、可制造、同部位逻辑」的制造配方材料中选 1 类组合。
- 同一特效多来源装时，生成器默认策略（建造阶段可定，建议：优先最高装等样本，可覆盖）。

## 6. 运行时职责（方案 B）

统一（或门面）管理器职责建议：

1. **Load** line / 方向 / 等级 / 配方法术 / 附魔 ID / 部位 / 类型元数据。  
2. **OnDisenchant(player, itemProto, currentPermEnchantId)**：按 §5.3 组池、掷骰、在满足前提下 `learnSpell`（技能书互斥按同向覆盖）。  
3. **OnEnchantCast(player, formulaSpell, item)**：附魔成功后按 §5.3 尝试领悟「当前链的下一级」。  
4. **Apply**：`EffectEnchantItemPerm` 使用公式对应附魔 ID；允许直打最高已知档；换向覆盖。  

`EnchantUpgradeMgr`（冲击式原版链）独立保留。旧 `enchant_comprehension_map` / `variant` 已退役，领悟只读 `enchant_line`。

## 7. 数据与生成器

- 离线工具扩展 `tools/enchant_comprehension/`：扫描 item_template + Spell.dbc，按签名分 A/B，产出 DBC 增量与 SQL line 表。
- ID 分配落在空闲且 `<65536` 的法术段；附魔 ID 独立段。
- 客户端 patch（如 `patch-3.MPQ`）与服务端 DataDir 同步发布。
- 分批顺序建议：  
  1) 运行时 + 表结构 + 1 条原版多向（十字军）+ 1 条特效多向（削骨或旋风迁入）  
  2) 武器命中触发批量  
  3) B 族装备 PROC  
  4) A 族单轴  
  5) 查漏补缺与数值调参

## 9. 留给建造者的决定

- 具体表名与字段布局（需支持：底座、方向、rank、formula、enchant、slot mask、axis type、试剂）。

- B 族批量时：强度轴/时间轴的具体代号与曲线表（默认模板已锁，见 §5.1.1）。

## 10. 成功标准（框架阶段）

- 十字军：训练师学会底座 → 施放有概率悟方向 1 → 再施放逐级悟高档；分解底座装悟不出方向 1；分解已打方向 k 的装可补齐 ≤k。  
- 特效线：分解得 rank 0 → 施放进方向；直打最高已知档；装备可交易。  
- A/B 分类与部位锁在抽检样本上正确。  
- 客户端能显示新配方名称（patch 同步）。
